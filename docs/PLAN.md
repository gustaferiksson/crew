# Crew plan

Native SwiftUI client for Hermes Agent bots (iOS 27 + macOS 27, one multiplatform target, Liquid Glass). Talks to `hermes dashboard` (v0.21.7 on the test server) the same way Hermex's Bot Mode does, and reads/writes the shared `ui_meta["hermes-bots"]` so Hermex and Hermes Desktop stay in sync.

References: `docs/hermes-api.md`, `docs/hermex-features.md`, `docs/swiftui-guide.md`. Hermex source (MIT) is the protocol reference, not a code source.

## Decisions

- XcodeGen `project.yml`, single target, `supportedDestinations: [iOS, macOS]`, bundle `dev.gustaf.crew`, `.env` signing (team 82K3YC8HVF) via `build.sh`, like tinecast/rinse/knyt.
- Swift 6, default MainActor isolation, `@Observable` stores in the environment, no per-view view models.
- Auth: path A (cookie login via `/auth/password-login`). Persist the session cookies (refresh token lasts 30 d, server refreshes itself) in Keychain; never store the password. On `401 session_expired|unauthenticated` show the login sheet again. Path B (PKCE bearer tokens) is the later upgrade.
- WebSocket: fresh `ws-ticket` per connect, passed as `?ticket=`; subprotocol header only as fallback.
- Session ids: runtime id (live calls/events) and `stored_session_id` (REST/history) are distinct types in the client, never mixed.
- History: load past turns from REST `GET /api/sessions/{stored_id}/messages` (includes tool calls and results) so the work log is complete on reopen; WebSocket history is too lossy.
- Verification: no driving windows on the Mac. A `-snapshot <name>` launch argument renders a named screen with fixture data to PNG and exits (tinecast `-settingsSnapshot` pattern); iOS via headless `simctl boot` + `simctl io screenshot`.
- Commits: one commit per layer on `main`, no push.
- Transport: one `URLSessionWebSocketTask` JSON-RPC client (actor) with ping, reconnect and `session.events.since` replay; REST for history, profile assets and cron.
- Connection state: server may sit behind a VPN. One observable `connection` state (connected, connecting, offline/unreachable, signed out) driven by the gateway socket and `NWPathMonitor`; shown as a glass banner/pill in the list and chat, composer disabled while offline, cached bots and transcripts stay readable, auto-reconnect with backoff and on network change. Distinguish "server unreachable" (VPN off) from "signed out".
- Push: `crew-push` Hermes plugin sends to APNs directly (token .p8 on the host, no relay, no NSE); design in `docs/push.md`. Approve/Deny actions from notifications in v1.1.
- Push scope (crew-push 0.3.0): only the profile's canonical Bot Chat (the compression tip of the session titled exactly `Bot Chat`, looked up read-only in the profile's `state.db`) and `cron` routines notify. The old native-platform denylist let `api_server`/`cli` sessions (another agent driving Hermes) push turns that Crew never shows.
- Payments (#9): bots pay through Hermes `browser_vault`; every fill needs Approve Once in Crew, one card per shop copied server-side from a master card, iframe checkouts unsupported. Plan and threat model in `docs/payments.md`.
- Persistence: Codable JSON cache in Application Support (bot list, last transcript per bot) for instant launch. No SwiftData.
- Markdown: own block renderer (from guide), no packages for v1.
- Transcript has no bottom scroll edge effect (`.scrollEdgeEffectHidden` for `.bottom`); content scrolls plainly under the glass composer, the top keeps the soft effect.
- Snapshots: `./snapshot.sh` runs the Debug app with `-snapshot <name>` (screens listed in the script; fixture `Connection`, `BotStore` and `ChatSessions`, no network or Keychain; `bot-page` is the real `ChatScreen` with the inspector open on macOS (attached in the fixture, since the app attaches it in `BotsView`) and the pushed bot page on iOS; `layout` and `layout-inspector` are the real `BotsView` with a favourite (Ada) or a row (Pixel) selected and its chat open, the latter with the inspector; `chat-dictation` is the listening composer); macOS renders light + dark in an offscreen window under `.accessory` policy, captured with `CGWindowListCreateImage` into the sandbox tmp dir and copied to `snapshots/`; iOS uses a headless iOS 27 simulator + `simctl io screenshot`.
- Session persistence: one Keychain item (`session`) holding server URL, pinned `install_id` and the cookie jar as `{name,value,domain,path,expires,secure}`; ephemeral `URLSession` per app, cookies re-saved whenever a refresh sees them change. Server URL and username live in UserDefaults for prefill.
- Keychain: data-protection keychain on both platforms; the Mac build needs `CREW_PUSH=1` signing (its profile supplies `application-identifier`, no keychain-access-groups needed), and the switch dropped sessions stored in the old login-keychain item.
- Server checks: `auth_required` must be true and offer `basic`, version >= 0.21.3 after stripping `+`/`-` suffixes; `install_id` mismatch on refresh signs out ("identity changed"), a fresh sign-in re-pins.
- Connection state (REST-derived until layer 2): 10 s request timeout; URLError timeout/DNS/connect/lost/offline and HTTP 502/503/504 mean unreachable (keep cookies, retry 2, 4, 8, 16, 30 s); any 401 on an authed call means signed out; unsatisfied `NWPathMonitor` path means unreachable at once, any satisfied path change resets backoff and retries.
- Login is a full-window screen swapped in by `RootView` when signed out, not a sheet.
- Gateway (layer 2): `Gateway` actor owns the socket and its backoff (1, 2, 4, 8, 16, 30 s); each connect runs `/api/status` (install_id check) then `POST /api/auth/ws-ticket`; a 401/403 upgrade or 4401 close switches to the subprotocol ticket for the rest of that gateway's life; ticket 401, identity change or unsupported server stop it and sign out.
- Connection state now comes from the gateway: connected after `gateway.ready` + `client.capabilities`, unreachable while backing off (automatic retries don't flip back to connecting), unsatisfied path disconnects at once, any satisfied path change reconnects. REST `GET /api/profiles` is gone.
- Gateway streams (`statuses()`, `events()`, `serverRequests()`) are broadcasts: every call returns a new stream, so stores and chat screens subscribe independently. `gateway.ready` is re-emitted on `events()` after each (re)connect as the reload signal.
- Wire decoding: explicit snake_case `CodingKeys` (no key strategy, so `ui_meta` keys round-trip), unix-second dates (`.secondsSince1970`), `JSONValue` for open payloads.
- Bot list: `profiles.list {include_sessions: true}` over the socket, cached as `bots.json` in Application Support; `ui_meta["hermes-bots"]` decoded into `BotMeta` with unknown keys kept in `extra`; reload on `gateway.ready`/`sessions.changed` (300 ms coalesce), when the last busy bot goes idle, and every 2 s while the app is active (v0.21.7 has no `profiles.changed`, nothing watches `profile.yaml`, and the server memoizes `profiles.list` rows by file signature); an unchanged roster or status map is not reassigned.
- Live status: `session.active_list` after each roster read, and every 2 s while inactive only when a bot is working/waiting, matched on `session_key` against canonical `id` and `resolved_id` (ambiguous keys ignored). Only `working` and `waiting` count as busy: `starting` is an agent build (a cold `session.resume` after the 20 s orphan reap, or `session.create`) with no turn running, and showed Working on every reopened bot after a reconnect; Hermes Desktop ignores it too. The poll has no approval/question distinction, so `waiting` takes its kind from `srq-` requests seen for that runtime id, else nil.
- Read state syncs through the profile's own `ui_meta["crew"] = {session, messages}` (the canonical chat's `resolved_id` and `message_count` when last viewed, written with its own `crew` revision so Desktop/Hermex writes to `hermes-bots` never conflict); positions order by session id (timestamp-prefixed, so a compaction tip sorts after its root) then count, unread is `position > max(server marker, local overlay)` and the 2 s `profiles.list` poll carries it to other devices.
- `markSeen` only ever moves the marker forward: the in-memory overlay updates the dot at once, a per-bot writer sends at most one `profiles.configure` per 2 s (coalescing to the latest value), and on `ui_meta_conflicts` re-reads the roster and writes again only if the server value is still lower; overlay entries drop once the server catches up.
- Bots with no marker anywhere (including old `{lastReadAt}` markers) count their current position as read on first sight, in memory only (no write, so activity before a relaunch is read until some device opens the bot); the UserDefaults `seenActivity` migration is gone.
- Unread tracks `message_count`, not `last_active`: v0.21.7's `canonical_session.last_active` is the raw `last_activity_at` heartbeat (prompt time, touched at most every ~2 min) and never moves when a reply lands, while `message_count` bumps on every stored message including the final reply (verified on `crew-test`: a reply finishing after the chat was left is unread on both clients, opening on either clears both). Desktop's `last_read_at` session watermark was rejected: the canonical Bot Chat is hidden from session lists, so reading it costs a call per bot per poll, and Desktop doesn't paint bot unread from it either.
- Sidebar ordering: hidden bots excluded, pinned bots only in the Favourites tile row, then sections A to Z by `sectionName` (bots with an id but no name are unfiled), unfiled last under "Other" only when named sections exist; within each group waiting > working > unread > newest `last_active`.
- Gateway testing without the GUI: `Tests/fixtures/fake_gateway.py <ws port> <http port> <normal|reject-query|silent|signedout>` (needs the `websockets` package in a venv) serves `/api/ws` (incl. `profiles.configure` with revision CAS and one forced conflict for `scout`, `profiles.get_asset` for `ada`) and `POST /api/auth/ws-ticket` on the second port; drive it from a scratch `swiftc -swift-version 6 -default-isolation MainActor` harness compiling `Gateway.swift`, `GatewayTypes.swift`, `Hermes.swift`, `BotStore.swift`. `Tests/fixtures/profiles.list.v0.21.7.json` is a scrubbed real roster.
- Default look (Hermex): a bot is custom when `custom` or `shape`/`color` is set; `default` without custom look is a #8b5cf6 squircle, otherwise each missing field comes from Hermex's 64-bit FNV-1a of the profile name (its offset constant 1469598103934665603, kept for parity) over the 7 non-blob shapes and 8 colours.
- Sidebar faces take their mood from `BotStatus` (working sways, waiting looks curious, failed looks sad). `.failed` is never stored by the live `BotStore` (the sidebar fixture sets it directly to render the sad face): `ChatSessions.status(of:in:)` derives it when the store says idle/unread and that bot's open chat ended its last turn in an error, and the row shows a red "Failed".
- One look everywhere: `BotMeta.look(name:)` resolves the default-look rule (sidebar, tiles, chat pill, inspector) and seeds `ProfileDraft.Identity`, so the editor starts from and resets to what the bot actually looks like.
- Row dates are iMessage style via `Date.FormatStyle` (locale-aware): time today, Yesterday, weekday within the last 7 days, then day + abbreviated month (`3 Sep`), adding the year outside the current year.
- Failed Pin/Unpin shows an alert with the server's message.
- App icon: Icon Composer bundle `Sources/AppIcon.icon` (pink #ec4899 tile, white avatar blob with attentive eyes; dark variant flips to a pink blob with white eyes, tinted/clear are automatic), written by `icon/generate-icon.py`, which also renders previews into `icon/previews` with Icon Composer's `ictool`. Pink is unused by the sibling apps.
- Photo avatars: `profiles.get_asset` for `has_avatar` bots unless `imageKind` is `shape`, fetched once per launch and again when the `hermes-bots` revision changes, raw bytes cached in Caches/avatars/<name>, 256 px ImageIO thumbnails in memory; a pin write carries the photo revision forward. A photo draws in the squircle body's own box (84 % of the avatar frame, 8 % inset, 0.28 corner radius), so it is the same size as shape avatars in every row, tile and pill.
- Pin/Unpin writes the whole received `hermes-bots` object with `pinned` flipped via `profiles.configure` and `ui_meta_expected_revisions` (missing revision is 0); on `ui_meta_conflicts` it reloads the roster and retries, 3 tries.
- Bot list shell: one `NavigationSplitView` (selection by `Bot.ID`, pushes on iPhone), `.searchable(placement: .sidebar)` filtering title, name, role and preview into a flat list, favourites as a 3-column tile grid, Pin/Unpin in context menus and leading swipe; selecting a bot (or it changing while selected) calls `markSeen`; the detail column is a `NavigationStack` around `ChatScreen(bot:)`, whose composer shows the offline state, so the connection pill sits only under the sidebar.
- Gateway testing without the GUI: `Tests/fixtures/fake_gateway.py <ws port> <http port> <normal|reject-query|silent|signedout>` (needs the `websockets` package in a venv) serves `/api/ws` and `POST /api/auth/ws-ticket` on the second port; drive it from a scratch `swiftc -swift-version 6 -default-isolation MainActor` harness compiling `Gateway.swift`, `GatewayTypes.swift`, `Hermes.swift`, `BotStore.swift`. `Tests/fixtures/profiles.list.v0.21.7.json` is a scrubbed real roster.
- Model quick switch: `ModelSwitcher` (owned by `BotsView` for the selected bot) loads `model.options` (its top-level `model`/`provider` is the current choice) and changes the default model through the shared `changeModel(of:to:confirmation:via:)` (`profiles.configure` model section, `confirm_required` asks, then resends with `confirm_expensive_model`). Entry points: the inspector Info Model row (menu with checkmarks, spinner while saving, alert on failure) and a Model submenu in the persona pill's context menu.
- Chat column: transcript and composer share one frame, the full column width with 16 pt margins (no max width); the composer is a `safeAreaBar` over a soft bottom scroll edge (a hard edge drew an opaque band and divider), and on macOS the composer gets the legacy scroller's width as trailing padding so both right edges line up.
- Bot inspector: `BotInspector(bot:models:isPresented:)` holds avatar, a Routine glass action circle and Messages-style text tabs (Info/Tasks/Routines, the selected one in a glass capsule). On macOS `BotsView` owns the flag and attaches `.inspector` to the `NavigationSplitView` itself, so the panel is a full-height trailing column like Messages' info panel and the toolbar only spans sidebar + chat (the persona pill centres in the chat column with no offset). The column is flexible (`inspectorWidth` min/ideal/max). A glass xmark close button sits in the inspector's own toolbar section at its top-leading corner: a `.cancellationAction` toolbar item in `BotInspector` (macOS only, shown only while `isPresented`, since SwiftUI keeps the hidden inspector's content alive and the item would otherwise sit in the chat toolbar; `.navigation` lands in the chat column). An overlay in the title bar row lost most clicks to `NSTitlebarView`, which owns the top ~32 pt as a window drag area. As in Messages' Info panel; clicking the persona pill again also closes it. There is no chat toolbar toggle. iOS pushes the same page from `ChatScreen`. `BotsView` also owns the selected bot's `ModelSwitcher` so the pill menu and the inspector share one.
- Window size (measured with `-snapshot <layout screen> -measure YES`, which logs `contentMinSize`, column widths and toolbar hit tests): no maximum, minimum height ~200 pt, minimum width sidebar 240 + chat 320 = 560 (320 with the sidebar collapsed); chat content, A2UI cards, tables, charts and maps all stay under the 320 column minimum. With the inspector open, macOS 27 `NavigationSplitView` + `.inspector` makes the minimum sidebar + chat + 2 × the inspector's current width (1240 at 340), independent of content (an empty inspector does the same). Workarounds tried and rejected: an outer `.frame(minWidth:)` lays the content out at 1240 and clips it; zeroing the chat column minimum while inspecting reaches 880 but crashes in a constraint loop with some restored column widths; an `HSplitView` sibling is honest (840) but loses the full-height inspector, its toolbar section and the pill centring. Kept as is pending a design call.
- Chat transcript is a `LazyVStack` so column resizes (inspector, window) only lay out visible turns; sidebar rows read their own status so streaming deltas never re-render `BotsView`. The jump-to-latest arrow hangs 12 pt above the composer bar, and the message field has a background fill behind its glass so content scrolling under it never shows through (the bottom scroll edge effect stays hidden).
- New Bot (compose) sits at the leading edge of the chat column's toolbar on macOS, like Messages; the sidebar toolbar keeps the account menu. iOS keeps both in the list toolbar.
- Timestamp reveal is iMessage-style: only user bubbles and their attachments slide left; the timestamp column slides in from the trailing edge for every row over a fading background backdrop, so it covers the end of full-width assistant lines instead of moving them. The column is the measured width of a time label and sits 8 pt into the trailing padding; bubbles move exactly that width. Both the touch drag and `TrackpadSwipe` report raw travel and `ChatView` scales it linearly to a third (full reveal after 3x the width, then clamped), springing back on release.
- Swipe timestamps on macOS: SwiftUI has no scroll-wheel gesture input, so `TrackpadSwipe` installs a local `.scrollWheel` monitor while the transcript is in a window, consumes only dominant-horizontal two-finger swipes inside its bounds (and their momentum), and springs back on release. iOS keeps the touch `DragGesture`. Swipes that start over a nested horizontal `NSScrollView` (code blocks, attachment rows; found by hit-testing the window) that can still scroll in the swipe direction, and rightward swipes, are left alone.
- The transcript scrolls to the bottom (the sentinel's id, see "Keyboard and scrolling") on every transcript change while the reader is at the bottom; `.defaultScrollAnchor(.bottom)` alone left new turns (e.g. one sent from another client and picked up on reattach) below the composer once `ScrollPosition` held a view id.
- Tasks: one `TodoItem` (status enum, tolerant decoding) and one source of truth, `ChatSession.todos`; the Tasks tab reads the bot's session from `ChatSessions`, so it is empty until that bot's chat has been opened.
- Routines: `cron.manage {action, profile}` over the socket (list always with `include_disabled: true`), jobs filtered by `[bot:<name>]` tag only when the reply lacks `scoped`; tool errors arrive as `{success: false, error}` and are surfaced as such.
- Run Now is REST `POST /api/cron/jobs/{id}/trigger?profile=` because `cron.manage` has no run action; `Connection.urlSession` is internal for this.
- New routines are named `[bot:<profile>] <title>` (Desktop interop), use Desktop's default delivery (local), and are scheduled by presets (hourly, daily, weekdays, weekly) or a raw cron/interval/phrase; cron times follow the server's Hermes timezone, so the schedule is shown as written and the next run in local time.
- Routines refresh on `cron.changed`, `gateway.ready`, after every mutation and every 20 s while the inspector is open (`cron.changed` only watches the gateway's own HERMES_HOME).
- Profile editing: after every save the inspector calls `BotStore.reload` so sidebar titles and photos update at once (no waiting for `sessions.changed`).
- Profile data: the inspector owns one `@Observable ProfileDraft`; load is `profiles.describe` + `profiles.list` (the only source of `ui_meta` and its revision) plus `profiles.get_asset` when `has_avatar`, rerun when the gateway changes; a reload only replaces fields that have no unsaved edits (a reload keeps the old fields on screen instead of flashing spinners).
- Profile save: one `profiles.configure` with only dirty sections, judged per section from `applied.*` (never `ok`); the whole `hermes-bots` object is sent with only changed keys overwritten so Desktop keys survive; a `ui_meta_conflicts` reply re-reads the roster, resets name and look, and sets `notice`; other failures set `notice` too, shown inline under the name with Try Again.
- Toolsets are read and written through the dashboard Tools page API (`GET /api/tools/toolsets?profile=`, one `PUT /api/tools/toolsets/{name}` per changed row), not `profiles.describe`/`enabled_toolsets`: 0.21.7's describe takes a composite pin like `platform_toolsets.cli: [hermes-cli]` (the default profile) literally and reports every toolset off, and the REST path also covers `stt` (`stt.enabled`) and Discord-only toolsets. The last enabled one still can't be switched off.
- Soul and Instructions are separate: Soul is SOUL.md (`soul` in describe/configure), Instructions is the `agent.system_prompt` overlay in the profile's config.yaml (`GET /api/config?profile=&include_defaults=false`, `PUT /api/config?profile=` with `{"config":{"agent":{"system_prompt"}}}`, deep-merged, so clearing writes `""`). A `display.personality` set on the server replaces the overlay at injection time. The Info tab edits Description, Instructions and Soul in place.
- Avatar photo: PhotosPicker on both platforms (a macOS file importer needs the user-selected-files sandbox entitlement); ImageIO downscales to a 1024 px JPEG (falls back to 768/512) under the 2 MB cap, uploaded with `profiles.set_asset` only after the `ui_meta` write succeeds; reset clears the asset and drops shape/colour/expression with `custom: false`.
- Profile fixtures: `Tests/fixtures/profiles.describe|model.options|profiles.configure(.conflict)|profiles.set_asset|profiles.get_asset.v0.21.7.json`, scrubbed real payloads (round-trips run on `crew-test`).
- Chat session: `ChatSession` per open bot resolves Bot Chat as `canonical_session.id`, else `session.list {title: "Bot Chat", include_hidden}`, else `session.create {hidden, follow_profile_config}` followed at once by `session.title {title: "Bot Chat"}` so the hidden, titled row exists before any prompt (create writes none; a runtime reaped before the first prompt resumed untitled and visible, leaving the bot with no `canonical_session`, so no time or Working); then `session.resume {omit_messages, inline_images: false}` for the runtime id and REST `/messages?order=latest&limit=500&include_compacted=true` (latest 500 rows only) for history.
- Attach while running: drop the history turn matching `inflight.user`, re-begin it at `turn_started_at` and replay ring events from the last `message.start` (else seed `inflight.assistant`).
- Replay cursors belong to the session: reattach asks `session.events.since` from its own last applied seq and a history load from 0 (the whole ring), never a gateway-wide cursor, which live events advanced before the session had applied them, so a turn finishing during a history fetch lost its `message.complete` and kept Stop showing.
- Reconnect: on `gateway.ready` re-resume; same epoch and runtime id and an untruncated `session.events.since` without a new `message.start` apply the replay, anything else reloads history (a replayed start can't be matched to its prompt, since `inflight` only describes the turn running now). Live events are deduped by `seq`; a replayed turn's finish time is when it was applied (events carry no timestamps).
- Server requests answer on the srq id with `{choice}` (approval) or `{answers: {qid: text}}` (clarify, `{}` cancels); replayed `open_requests` use the same reply. Kinds Crew can't render are declined with 4404 (not shown here) so another client can still answer; `request.cancel`/`approval.cancelled` clear the card.
- `thinking.delta` is the TUI spinner face (verified on 0.21.7), never transcript text; `reasoning.delta`/`reasoning.available`/`message.complete.reasoning` become thinking rows. `tool.generating`, `status.update` and the todo list (`todo.updated`, `tool.complete.todos`, `todo_state`, revision-monotonic) are published on `ChatSession` for the UI and the Tasks panel.
- Send while running: Steer = `session.steer` (a user bubble that splits the run where Hermes takes it, matching the `display_kind: steer` history row; see "Composer, drafts and sends"), Queue = local queue submitted one per `message.complete`, Stop = `session.interrupt` and drops the local queue back into the draft.
- `ChatSessions` (environment) holds one `ChatSession` per bot per gateway, created lazily by `ChatScreen(bot:)` and kept running (so every opened bot re-resumes on each `gateway.ready`) until the gateway changes or the user signs out. `ChatScreen` marks the bot seen whenever its `last_active` changes while open and maps waiting/working/failed to the pill avatar's mood. No transcript disk cache yet.
- @-mentions (Desktop parity): `@` at the end of the draft lists up to 8 other roster bots (prefix on handle or title; `default` is `@hermes`), then `@file:`/`@folder:` rows from `complete.path` on the runtime session. A mention is an `@handle` or `@title-slug` token in the text, never separate state; in a sent bubble a token that names a mentionable bot (the roster minus the current bot, or the room's members) renders inline as "@ (avatar) Name": a plain "@" glued by a narrow no-break space to a white-translucent sheen capsule with a 1 pt white hairline holding the bot's 16 pt avatar (`ImageRenderer` snapshot, cached, embedded as `Text(Image)`) and its `Bot.title` in semibold, never the typed `@handle` (a `TextRenderer` over a `customAttribute` run; true `.glassEffect` cannot be drawn per text run). A bubble resolves its tags once per body and hands them to its tap overlay, whose `Text.LayoutKey` closure reruns on every scroll frame, so it never re-parses the text. Tapping a tag (a `crew-mention:` link plus a clear overlay over the capsule) never navigates: it opens a peek (`MentionPeek`, spec in `docs/flows/mention-card.md`) with the bot's live status and what the mention caused, read from the sender's own rows by `mentionExchange` (the turn's `message_agent` `message`, then the reply paired like #32, or Sending, Waiting, Delivered, Not delivered, Relayed; a plain mention shows the bot's latest preview). On iPhone and iPad it is a sheet at `.medium` whose `.large` detent (or a tap on the mention card) swaps in that bot's live `ChatScreen`; on Mac it is a popover at the tag whose mention card opens the bot's chat in its own window (`WindowGroup(for: Bot.ID)`), so the main window keeps its chat; the composer text stays plain (no attributed `TextField`) and no chip row shows anywhere. Only `prompt.submit` (send and queue) appends Desktop's identification note (from `hermes-bots/plugin.tsx`) plus one sentence of ours asking for brevity (no queueing or delivery narration, at most one short line after `message_agent`, the reply relayed in one line), steer does not; `Prompt(raw:)` cuts it off history like the other server suffixes. Return does not pick a suggestion. The transcript re-pins to the bottom when the composer bar grows (picker, cards) while it was at the bottom (`ChatView`'s `BottomEdge`), so the last reply never sits under the bar.
- Live work log header shows `status.update` text, else "Preparing <tool>" from `tool.generating`, after "Working for" on the last turn.
- iOS `scenePhase`: background calls `Connection.suspend()` (state connecting, socket closed); returning from background calls `retry()`. Launch's inactive to active is ignored because the network monitor already connects.
- Push client: `PushCenter` (owned by the platform app delegate adaptor, in the environment) reads authorization at launch and asks for alert, sound and badge (the normal Allow prompt) on the first connection while undetermined or provisional; time-sensitive comes from the entitlement, its authorization option is deprecated.
- Push registration: `POST /api/plugins/crew-push/devices` on every connect and on token, authorization or prefs change, with exactly the plugin's `DeviceIn` shape (no bundle id or install id fields; the plugin's `install_id` comes back in the reply and filters taps); 404 means "not set up on server" and is not retried until the next connect; sign-out deletes the token first; a changed token deletes the previous one.
- Push environment: `#if DEBUG` sends `sandbox`, else `production` (Xcode drops custom `INFOPLIST_KEY_*` settings, so it isn't read from Info.plist); `APS_ENVIRONMENT` drives the entitlement value per configuration.
- Push signing: `CODE_SIGN_ENTITLEMENTS` picks `Entitlements/Crew-iOS|macOS.entitlements` by `PLATFORM_NAME`; `./build.sh` blanks it unless `.env` sets `CREW_PUSH=1` (then `-allowProvisioningUpdates`), since signing needs Push on the App ID.
- Push builds: `CREW_PUSH=1` and `./device.sh` pass `-allowProvisioningDeviceRegistration` so automatic signing registers the Mac and iPhone itself; `./device.sh` builds `generic/platform=iOS`, then installs and launches with `devicectl` on the first connected iPhone (`DEVICE=<udid>` overrides).
- Read elsewhere: after a read marker write lands, Crew posts `POST /api/plugins/crew-push/read {token, profile, session_id, read_at}` (so inherits the 2 s per-bot throttle); the plugin sends a background push (`content-available`, priority 5, `crew.kind = read` with profile and `thread-id`) to every other registered device, whose app delegate removes that bot's delivered notifications and zeroes the badge when none remain. iOS gets `UIBackgroundModes: remote-notification` from `Info-iOS.plist` (Xcode drops `INFOPLIST_KEY_UIBackgroundModes`); macOS only receives it while Crew runs.
- Push presentation: `willPresent` hides a notification only while the app is active and that bot's chat is selected (profile match, any session); opening a chat clears that bot's delivered notifications by `thread-id`; a tap selects the bot and always opens its chat (no stored-session browser yet, so `session_id` is not used).

## Navigation

- macOS: modelled on macOS 27 Messages. `NavigationSplitView` sidebar (glass search field, favourites, sections, bot rows with avatar, bold name with an optional secondary " · role", time, two-line preview, unread dot) | chat (centred avatar + name pill floating over the transcript, glass composer at the bottom, glass toolbar buttons) | `.inspector` opened from the pill (large avatar, editable name, glass action circles, text tabs with a glass capsule on the selected one: Info, Tasks, Routines, Files; grouped glass-ish cards; glass xmark close button top-leading in the inspector's title bar row, the pill also toggles it).
- iOS: same split view collapsing to a stack. Root list: favourite tiles row on top, then bots iMessage-style (avatar, name, last line, time, unread/working dot). Persona pill opens the profile page (same content as the macOS inspector: Info, Tasks, Routines) edited inline.
- Tasks: per bot, the live todo list from `todo.updated` events of the current/last run plus scheduled cron jobs for that profile (`cron.manage {action: list, profile}` / `/api/cron/jobs`), with next run, last result, pause/resume/run now.

## Layers (each builds on a working previous one)

1. **Skeleton + login**: project, build script, app shell, server URL + username/password onboarding, `/api/status` probe, version check (>= 0.21.3), Keychain, sign out, unreachable-server state on login. Snapshot hook. Ends with: log in, see profile names via REST `GET /api/profiles`.
2. **Gateway client + bot list**: WebSocket JSON-RPC client, `profiles.list`, avatar renderer (8 shapes, 11 colours, eyes/expressions, photo asset), favourites (pinned) row, sections, live status via `session.active_list`.
3. **Chat**: open/create the "Bot Chat" session, history, `prompt.submit`, streaming `message.delta`, iMessage bubbles (user bubble with sharper bottom-right corner, no copy/action row on replies), centred day separators, swipe-left timestamps, glass jump-to-bottom, glass composer with mic + send, Stop/Steer/Queue while running. Minimal approval and question cards (answering `srq-` requests) land here because `client.capabilities {server_requests: true}` makes runs block on them. Swipe timestamps in pure SwiftUI; UIKit pan fallback only as last resort.
4. **Work log**: reasoning + tool events grouped under "Worked for Xm Ys" accordion (live "Working for" while running), thinking rows, tool rows with icon/verb/summary/success-or-error, "+N previous tool calls" collapsing, expandable details. Polished approval and question cards.
5. **Profile editor**: avatar (shape, colour, expression, photo, reset), display name, description, instructions/SOUL, model picker, Capabilities rows (Skills n/m, Toolsets n/m, MCP servers n/m) opening a sheet with a toggle per item and Done, enabling/disabling per profile, server row. Save via `profiles.configure` with revisions.
6. **Polish**: create/duplicate/delete bot, per-bot routines (cron) in the inspector, search, dictation, notifications for finished turns while backgrounded, app icon in an unused hue.
7. **Push notifications (MVP)**: APNs for finished turns, approvals and questions on iOS and macOS when the app isn't connected. Needs a small server-side Hermes plugin; design in `docs/push.md`.
