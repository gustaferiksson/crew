# Compact bot rows in a narrow sidebar (#143)

When the sidebar (bot list) is dragged or squeezed narrow, a bot row has no room for its name next to a status label like "Needs approval", and the two-line preview wraps into a few words. Below a width threshold every bot and group row switches to a compact version: avatar and name on one line. At normal width rows stay exactly as today.

## What Apple does

Messages on the Mac keeps one row layout for the whole list and changes it as the column narrows, never row by row; Mail and Slack do the same with their dense modes. The list keeps selection, scroll position and keyboard focus across the switch, and status that no longer fits as text moves onto the avatar as a badge (Slack's presence dot, Messages' Focus and typing badges). So: one decision for the whole list, taken from the column's width, with status carried on the avatar.

## Rule

- `BotsView` reads the sidebar `List`'s outer frame with `.onGeometryChange(for: Bool.self) { $0.size.width < compactRowWidth }` (the repo's `onGeometryChange` idiom, mapped to a `Bool` instead of the width), keeps it in `@State isCompact` and passes it to `BotRow` and `GroupRow` as an init parameter. The `Bool` only changes when the width crosses the threshold, so a live resize re-renders the rows once per crossing, not on every pixel. The outer frame includes the scroller, so shorter rows hiding a scroll bar can't flip the decision back.
- Threshold, per platform like the other row constants: **macOS 260 pt, iOS 300 pt** of sidebar column width. Derivation: a regular row needs its name column to hold a readable name (about 12 characters, "Ada Lovelace") beside the widest trailing label. Measured with the row fonts: macOS headline 13 pt bold "Ada Lovelace" 85 pt, subheadline 11 pt "Needs approval" 82 pt, plus the 4 pt spacing: 171 pt. The text column is the column width minus the sidebar list's own side insets, the 10 pt dot gutter, the 40 pt avatar, 12 pt avatar spacing and 12 pt trailing inset, so 171 pt needs about 255 to 265 pt depending on the list insets (checked in a render, and the constant adjusted if the render disagrees). The derivation uses the English labels; a longer localisation would want a wider threshold, which is a follow-up if Crew is localised. iOS: 17 pt "Ada Lovelace" 107 pt plus 15 pt "Waiting for you" 103 pt plus 4 pt is 214 pt, plus 12 + 52 + 12 + 12 pt: 302, rounded to 300.
- The sidebar column stays `min 240, ideal 320, max 400`, so the compact band is 240 to 259 pt on the Mac and 240 to 299 pt on iPad. 320 (the default) is always regular. Lowering the column minimum would widen the band and is a separate decision.
- iPhone: the list is the full screen width (at least 375 pt on iOS 27 devices), so iPhone never meets the threshold and is unchanged. iPad in a regular-width window: the sidebar column follows the same rule if the user narrows it; in a compact-width window (Slide Over, narrow Stage Manager window) the split view collapses to a stack, the list is full width again, and rows are regular.
- No locked value changes: rows keep `rowPadding`, `dotGutter`, `rowAvatarSize` and the iOS separator guide and macOS hairline on the text column (PLAN.md "UI values (locked)", bot list separators). The compact text column is one line, but it gets `.frame(minHeight: rowAvatarSize, alignment: .leading)`, so it is as tall as the avatar and the Mac hairline (an overlay on its bottom, offset `rowPadding`) still lands at the row's bottom; the iOS separator still starts at the name. Both checked in the renders.

## Compact row

- Kept: the unread dot in its gutter (same place and size as regular), the avatar at full row size, the bot's title in `.headline`, one line, truncated at the tail.
- Status badge: on the avatar's bottom-trailing corner, a 14 pt circle (Mac 13 pt). The avatar is knocked out under it with a 2 pt gap (a mask with a `.destinationOut` circle, not a ring painted in a background colour; the mask reaches a quarter of the avatar past its frame, so a working avatar's tilt is never clipped), so it reads the same over the Mac sidebar material, the selected accent row and in both themes. On shapes whose corner is empty (star, blob) the badge sits on the same corner of the avatar's frame, like a Messages badge on a non-photo contact. Colour and symbol match the trailing label it replaces, so status never relies on colour alone: Working green `ellipsis` (with the same `.variableColor.iterative` effect as the trailing label, which honours Reduce Motion), Waiting (approval, question, payment) orange `exclamationmark`, Failed red `xmark`. Idle and unread show no badge (unread already has its dot).
- Dropped: the " · role" suffix, the trailing time or status label, the two-line preview and the red "Draft:" line. A draft is still kept and shows again when the sidebar widens and in the chat's composer; the compact row has no room for it, as Messages' narrow list has none.
- Accessibility: the compact row is one element (`children: .ignore`, so the dot's own "Unread" isn't read twice) labelled "title, role" (or just the title), with the status as its value: "Unread", "Working", "Needs approval", "Waiting for you", "Wants to pay", "Failed", and "Draft" when a draft is pending, so VoiceOver loses nothing that the eye loses.
- Height: the row is as tall as the avatar plus `rowPadding`, a little shorter than a regular row (3 pt on the Mac: 40 against 43, measured). The switch reflows the list once. The rows keep their identity (same view type, same `.tag`), so the selection, scroll position near the selected row and keyboard focus are kept.
- Group rows: same rule, `GroupAvatar` and the room name; they have no status, so no badge. Their member list and time drop.

## Surfaces

- **Sidebar sections and favourites (Mac and iPad):** section headers unchanged. The favourites grid (three tiles of avatar, name, status) is already avatar-and-name and stays as is at every width.
- **Search:** name matches in "Conversations" and the plain name filter use `BotRow`, so they go compact too. "Messages" hits (`MessageHitRow`) keep their snippet at every width: the snippet is the result, a hit without it is useless, and they appear only while searching. Search field, "Searching…", offline and error lines unchanged.
- **Selection:** the selected compact row shows the system sidebar selection, unchanged. Arrow keys, Return, double click to open a window and type-to-select work as today (same `List(selection:)` and tags).
- **Context menus:** the Mac menu comes from `contextMenu(forSelectionType:)` on the `List` and iOS's from `.contextMenu` on the row; both stay, with Open in New Window, Pin/Unpin, Duplicate, Move to Section and Delete. Swipe to pin on iOS stays.
- **Chat, inspector, composer, push, chat windows:** untouched. Nothing here changes which bot is selected, unread or notified.
- **Live resize:** dragging the sidebar divider or shrinking the window across the threshold switches every row in the same frame, without animation (Messages doesn't animate it either), and back again when widened. No rows switch independently, since the decision is the column's, not the row's.
- **Light and dark:** the badge sits in a knockout of the avatar, so no background colour is painted; its colours are the system green, orange and red already used by the trailing labels; rendered in both.

## States

- **Empty list, loading, offline, error:** the "No Bots" view, spinner, connection pill (after 2 s) and alerts are overlays and bottom bars of the list, not rows; unchanged at every width. A cached roster offline shows compact rows with their cached statuses. Search results mix compact Conversations rows with regular Messages hits, as Mail mixes sender rows and message hits; rendered once.
- **Long names:** truncate at the tail on one line; the badge sits on the avatar, so it never competes with the name. A name with a role shows only the name.
- **Many bots:** the list scrolls as today; compact rows are shorter, so more fit.
- **Accessibility text sizes (iPad):** the threshold is in points, so larger text doesn't change when rows go compact; the compact name grows with Dynamic Type and truncates.

## Tests

- Unit (`CrewTests/CompactRowTests.swift`, macOS, unhosted): `BotRow` moves from `BotsView.swift` to `Sources/BotRow.swift` (with the row constants, `compactRowWidth` and `Date.rowLabel`) and joins the CrewTests sources. It hosts the real row (`isCompact: width < compactRowWidth`, the same expression `BotsView` uses) with the recorded `cold-open` roster and live sessions (an unread bot with a preview, and the same bot working) and measures its layout, as `CardHeightTests` does: just below the threshold the row is exactly the avatar's height (no preview lines) and its ideal width is the dot gutter, avatar, spacing and the name's own width, nothing else (no role, time or status label), and the working and unread rows are the same width; at the threshold the row is taller, wider and differs between working and unread. It also checks the threshold stays between the column minimum (240) and its default (320). Shown failing with the compact path disabled. The compact row's VoiceOver label and value have no automated check (an unhosted test gets no accessibility tree); they are read in code review.
- Live resize (Mac render): the `sidebar-compact` snapshot selects the group row near the end of the list in a tall window, then its offscreen capture moves the sidebar divider from its launch width up to 330 pt and back to 250 pt (crossing the threshold both ways, as a drag would) before capturing, so the render shows every row switched together and the selected row in compact form. Scroll position is not proven separately: the rows keep their identity and the row height changes by 3 pt, so the list keeps its offset. The split view has no autosave name (the `dev.gustaf.crew` domain holds no split view keys, checked read-only before and after a run), so moving the divider in the snapshot persists nothing.
- Renders, light and dark: a `sidebar-compact` snapshot, the real `BotsView` with the fixture roster (working, waiting, failed and unread bots, a photo avatar, a long role, a draft) and the sidebar column's ideal width set to 240 pt for that snapshot only. Mac offscreen like the other snapshots; iOS on a private iPad simulator created and deleted for this (landscape, sidebar beside the detail); iPadOS 27 honours the 240 pt column, so iPad reaches compact rows. Badge renders include a star or blob shape, a photo avatar and the selected row. The regular `sidebar` and `layout` renders are checked unchanged.
