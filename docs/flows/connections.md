# Inspector Connections section: a bot's MCP servers

Issue #184. A **Connections** section in the inspector's Info tab, right after Capabilities (the bot's other tool switches), lists the bot's MCP servers, adds them from Hermes' catalog or by hand, signs in to OAuth servers and turns them on or off. UI only: Hermes 0.22.5's `hermes_cli/web_routers/mcp.py` has every route.

## Settled constraints

- **Per profile.** Servers live in each profile's `config.yaml` (`mcp_servers`); every route scopes by `?profile=` (`_config_profile_scope` / `config_write_scope`). Verified on the server: `default` lists `files` and `icloud`, `crew-test` started empty, and an unknown profile answers 404. Every Crew call carries `?profile=<bot.name>` (also for the default bot), and writes repeat `profile` in the body, so a missing query can never write to `default`.
- **Routes:** `GET /api/mcp/servers`, `POST /api/mcp/servers {name, url | command, args, env, auth, bearer_token}`, `DELETE /api/mcp/servers/{name}`, `PUT /api/mcp/servers/{name}/enabled {enabled}`, `POST /api/mcp/servers/{name}/test`, `GET /api/mcp/catalog`, `POST /api/mcp/catalog/install {name, env}`, `POST /api/mcp/servers/{name}/auth`, `GET`/`DELETE /api/mcp/oauth/flows/{id}`. Cookie auth satisfies `_require_token`.
- **Status comes from Test.** The list is config only. When the Info tab opens Crew tests every enabled server at once (0.7 to 3.6 s each on the server): `ok` → "Connected · 9 tools"; not ok and `auth == "oauth"` → "Needs Sign-In" with a Sign In button; otherwise "Error" with Hermes' message. Disabled servers show "Off" and are not tested. `/test` answers 200 with `ok: false`, so Crew reads `ok`, never the HTTP status.
- **Changes apply to new chats** (`enabled` and new servers take effect on the next session); the footer says so.
- **Plugin servers** (`source: "plugin"`) are read only: "From <plugin>", no toggle, no delete.
- **Headers mean a bearer token.** Hermes' create route accepts only `auth: none | header | oauth`, with `bearer_token` for `header`, stored in the profile's `.env`. URL servers reject `args`/`env`; command servers reject auth. The Custom form offers exactly that: URL (Auth: None / API Key / Sign In) or Command (arguments, one per line; environment, `KEY=value` per line).
- **Catalog install** sends `env` only for the entry's `required_env`; fields whose name contains KEY, TOKEN, SECRET or PASSWORD are secure fields. The catalog carries no icons, so rows use a monogram tile. All 66 entries install synchronously today; a `background: true` answer just reloads.

## OAuth sign-in

`POST .../auth` returns a flow with `authorization_url`, whose `redirect_uri` is `<dashboard.public_url>/api/mcp/oauth/callback/<name>`; on this server that is `https://hermes.gustaf.dev/...`, reachable without the dashboard login (checked: unknown flows get Hermes' own "OAuth flow expired" page). Crew opens the URL with SwiftUI's `webAuthenticationSession` (`.shared` browser session, so existing logins are reused) and polls `GET /api/mcp/oauth/flows/{id}` every 1.5 s. The redirect is https on the user's server, which an app can't claim without an Associated Domains entitlement, so the browser sheet never completes by itself: the user sees Hermes' "Authorization received" page and closes it. Polling is the completion signal: `approved` (with `tools`) cancels the browser task and the row reads Connected; `error` shows the message. Closing the sheet does not cancel the flow (a DELETE right after the redirect could kill a sign-in still being saved); the row shows "Waiting for sign-in…" with a Cancel button that sends `DELETE`. Hermes ends an unanswered flow after 5 minutes. The authorization URL is never logged.

## Surfaces

- **Connections section:** each row is a monogram tile, the name (one line), and a status line (secondary; orange "Needs Sign-In"; red error text, up to two lines, the full text in the row tooltip (Mac) and context menu title). Trailing: a switch (enabled), or a small spinner while testing, saving or signing in. Needs Sign-In adds a **Sign In** borderless button. Context menu (Mac right click, iPhone long press) and VoiceOver actions: **Test**, **Sign In** (OAuth servers), **Remove…** (destructive). iPhone swipe: Remove (red, no full swipe). Remove asks first: "Remove Linear from Ada?", "Ada loses these tools in new chats.", **Remove** / Cancel.
- **Add Connection…** (`plus.circle`) after the rows opens the sheet.
- **Add Connection sheet** (NavigationStack, searchable): **Custom Connection…** first, then the catalog (monogram, name, one-line description; "Added" for installed ones). A row pushes its detail: description, address or command (the trust model asks users to inspect them), any required fields, how it signs in, and the entry's setup notes in a disclosure group. **Add** confirms, the sheet closes, the list reloads and tests the new server; an OAuth one then shows Sign In.
- **Empty:** "Ada has no connections." **Loading:** small spinner. **Couldn't load:** "Couldn't load connections." + Try Again. **Offline:** last list stays, every control disabled; reloads when back online. **Errors** on add, toggle or remove show Hermes' `detail` (such as "Server 'x' already exists") in red under the row or in the form.
- **Long content:** names and addresses truncate in the middle on one line; error text wraps to two lines; the column minimum (280 pt) is unchanged.
- Not a fifth tab: five text segments truncate "Connections" on iPhone (checked in a render), and the Mac's icon segments would have no iPhone counterpart.
- iPhone (pushed profile page) and Mac (inspector column), light and dark, all system Form styling.
