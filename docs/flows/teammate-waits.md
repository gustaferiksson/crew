# Waiting on teammates (#370)

When a bot has sent a `message_agent` request to a teammate and that delivery has not settled, its Bot Chat shows a compact "Waiting on teammates" card above the composer: who it went to, where it stands, for how long, and what to do. Hermes 0.23.4 adds the read-only `bot_delivery.list` method (`tools/bot_delivery_status.py`, `tui_gateway/contracts/groups_bot_relay.py`); Hermes Desktop shows the same card (`hermes-bots/teammate-waits.tsx`). Relates to #348 (typed delivery failures, `delivery-failure.md`) and `agent-messages.md`.

## Data

- `bot_delivery.list {profile: <this bot>}` returns `deliveries`, newest first: `delivery_id`, `target` (profile name), `target_handle`, `state` (`queued`, `claimed`, `working`, `waiting_on_you`, `failed`), `since` (epoch seconds of the receipt's last write), `preview` (the message, at most 140 characters), `waiting_on` (`clarify` or `approval`, only for `waiting_on_you`), `reason` and `error` (only for `failed`). Settled deliveries are not listed; failures stay listed for 24 h.
- `reason` is Hermes' typed vocabulary (`delivery-failure.md`) plus `unknown_outcome`: the target may have acted. Crew never resends a delivery and never offers to; there is no retry button.
- Polled every 5 s (Desktop's roster cadence; Crew's 2 s roster tick would scan every target's receipts twice as often for a strip that rarely has rows), only while that bot's chat is on screen and the app is active, one poll per chat screen. An older server answers method not found (code -32601 or a "method not found" message): the strip never shows and the chat stops polling until the connection changes.
- A failed poll (timeout, socket drop, offline) is not an empty answer: the last rows stay, marked stale (below), and polling continues.

## Surfaces

- Bot Chat on iPhone and iPad, Bot Chat in the Mac main window and the Mac chat window (`mac-chat-window.md`): the same card, in the composer's accessory stack. Rooms, Other Conversations and the inspector's conversation viewer have none (the strip is about one bot's own requests).
- Order, top to bottom: transcript, request card (approval, question, payment), this card, the pinned-card chip, the composer. A request card hides this card, like it hides the pinned chip, so the stack never grows past one decision at a time; the card returns when the request is answered. Room Reply chips live only in rooms, so they never meet this card.
- Shape: a Liquid Glass card (`glassEffect(.regular)`, 18 pt corners, a capsule for one line), the full composer width (the chat's 16 pt margin, no 560 pt cap), 14 pt side and 8 pt vertical padding. It is part of the composer bar, so the Jump to Latest arrow and the transcript's end hold treat it like the approval card, and it never sets a window's minimum height (no vertical `fixedSize`; at most 3 rows, so it is bounded). No header line: the card is labelled "Waiting on teammates" for VoiceOver only. One row per teammate: Desktop lists every delivery, Crew folds a teammate's queued deliveries into its most urgent row (waiting_on_you, then working, picked up, then queued) and counts the rest, so a lone queued row reads "3 queued" and a working row reads "Working on it, and 2 queued". A waiting_on_you row, a failure and any other live row are never folded into a count and keep their own row (a failure keeps its own Dismiss). Order: waiting_on_you first, then the other unsettled rows newest first, then failures newest first (the row the user must act on is never behind the cap); at most 3 rows, more sit behind a "+N more" button that counts rows. The card never scrolls.
- Row: one line, the teammate's 20 pt avatar, then the title (footnote, medium) and its status in one text (a failure sentence that already names the teammate is shown alone with the name in medium, never prefixed by the name again; VoiceOver drops the duplicate name too) (footnote, secondary; it wraps to 2 lines, truncating the status first), the age (footnote, secondary, monospaced digits, "now", "5m", "2h", "1d"; it keeps counting between polls), then Open (borderless, footnote, hit area padded to 44 pt tall with `contentShape`, not layout height) and, for failures only, a Dismiss X (secondary, its hit area padded to 44 pt wide and 32 pt tall with `contentShape`, not layout height). Each row also has a context menu (long press, right click) that shows the preview (up to 140 characters) and Hermes' `error` line for a failure, with Copy Message and, for failures, Dismiss; the preview and `error` are the row's VoiceOver value and the Mac tooltip.
- Status words: Queued; Picked up; Working on it; waiting_on_you reads "Needs your answer" for `clarify` and "Needs your approval" for `approval` in the accent colour (the one row the user can act on); a failure reads the typed sentence from `DeliveryFailure.explanation` in secondary text with a red `exclamationmark.circle` (colour is never the only signal); `unknown_outcome` reads "Outcome unknown. It may have acted, and Crew won't send it again." and never truncates (bot-to-bot messages are hidden from Bot Chats, so the copy never sends the user to look for one) An unknown reason shows Hermes' own `error` line, else "Delivery to <Bot> failed.".
- Open: opens the teammate's own chat, where its question or approval card is (main window: selects it, like a mention peek's open; Mac chat window: that bot's own chat window, the `openWindow(value:)` precedent; iPhone: pushes it). It resolves `target` against the roster by profile name only; a teammate the roster does not have yet (created since the last roster read) shows the handle, a generic generated avatar (so the name column stays aligned) and a disabled Open. It never falls back to this bot's own chat.
- The age is the time in the current state (`since` is the receipt's last write, so it restarts on each state change, as in Desktop), clamped to "now" when the server's clock is ahead.
- The first poll runs when the chat appears and when the app becomes active, then every 5 s; a poll is never doubled.
- Open and Dismiss act on the row only. They never send, steer or clear the composer draft and never move focus into or out of the field (plain buttons, no default-action role).
- Dismiss hides a failed row and persists: `dismissed-deliveries.json` in Application Support (id to dismissal date; atomic write per change, never `UserDefaults`, like `pins.json` and `drafts.json`), per device, cleared on sign-out. Entries drop once a successful poll no longer lists the id (Hermes' 24 h window or a new delivery) and after 24 h regardless. Only failures dismiss; a live delivery cannot be hidden.
- Bot list, push, inspector: unchanged. The sender's row keeps its own Working or Waiting badge from `session.active_list`; the teammate's row already shows its question as Waiting and its unread dot, which is where Open leads. No push is added.

## States

- Empty (no unsettled delivery, all failures dismissed, a server without the method): no card, no gap; rows appear and leave with the usual `.smooth` animation (none with Reduce Motion).
- Stale: the last poll failed and rows exist: the rows dim (secondary opacity) and a caption "Couldn't refresh. Showing the last known state." sits under the rows; Open still works, Dismiss still works. Offline (connection lost) is the same state, never a separate banner (the chat already shows its own offline reason). With no rows and a failing poll: no card.
- Failure reasons: every Hermes reason has a sentence (`DeliveryFailure`); a code Crew has no sentence for shows `error`, never the raw code.
- Long names and previews: the title truncates, the status wraps to 2 lines then truncates, the preview is never shown inline (it is the row's VoiceOver value and the Mac tooltip). Many rows: 3 plus a "+N more" button that expands the card to every row (the card then grows with the rows, still inside the composer bar's height cap) and reads "Show Less" to collapse again. Accessibility sizes: the name truncates, the status wraps to as many lines as it needs, text capped at accessibility size 3 like the approval card.
- VoiceOver: the card is one container labelled "Waiting on teammates"; each row is one element "<Bot>, <status>, <age>" with the preview as its value and Open and Dismiss as its actions (and visible buttons).
- The card hides while a voice message replaces the composer with its recording row, stays visible offline (stale) and does not change while the sender itself is Working. A hidden target still opens (it is a roster entry); a deleted one keeps a disabled Open and the handle. Mac rows are keyboard focusable and Space activates Open; Reduce Transparency and Increase Contrast use the system glass fallbacks.
- Light and dark: system materials and secondary styles only.
- Keyboard focus: while the card shows, the composer keeps focus; tapping the card does not dismiss the keyboard.
