# SwiftUI multiplatform (iOS + macOS) guide for Xcode 27

Toolchain verified on this machine (2026-10-13): Xcode 27.0 (27A266a), Swift 6.4, iPhoneOS27.0 and MacOSX27.0 SDKs, XcodeGen 2.46.0. Every code sample in section 5 compiled cleanly (zero warnings, Swift 6 language mode, MainActor default isolation) for both `platform=macOS,arch=arm64` and `generic/platform=iOS Simulator` in a throwaway project at `scratchpad/Probe/`, built from the exact `project.yml` in section 1 (names swapped). The `markdownBlocks` parser was also executed against a sample with a heading, a nested ordered/unordered list, a fenced code block, a quote and a rule, and produced the right block kinds, markers and depths.

## 0. The one blocker to know about first

Only **iOS 26.3, 26.4, 26.5 simulator runtimes** are installed. With an iOS 27.0 deployment target, `xcodebuild -showdestinations` lists every simulator as incompatible ("iOS Simulator 26.x doesn't match Probe.app's iOS Simulator 27.0 deployment target"). So, today:

- `-destination 'generic/platform=iOS Simulator'` **builds** fine (no runtime needed).
- Running or testing on a simulator requires the iOS 27 runtime: `xcodebuild -downloadPlatform iOS` (several GB, so do it deliberately), or run on the paired physical iPhone if it is on iOS 27 (it shows up as a compatible destination).
- Don't lower the target to 26 just to use the old runtimes. Every Liquid Glass API is 26.0 anyway, but the 27-only APIs listed in section 2.3 would then need `if #available` gates, which the "latest OS only" rule rules out.

## 1. Project setup

### Recommendation: one multiplatform app target, generated by XcodeGen

| Option | Verdict |
|---|---|
| Separate iOS and macOS targets | No. Duplicate settings and two schemes for the same code. Xcode's own multiplatform template has been one target with `SUPPORTED_PLATFORMS` since Xcode 14. |
| Hand-made `.xcodeproj` | Works, but pbxproj diffs are unreviewable and every repo of yours already avoids it. |
| Tuist | Not installed, heavier, and nothing in your repos uses it. |
| Pure `Package.swift` (roost style) | Fine for a macOS-only tool, but SwiftPM can't produce an iOS app bundle (no Info.plist/entitlements/asset catalog/signing), so it fails the iOS requirement. |
| **XcodeGen `project.yml` + optional local Swift package** | **Use this.** It's what tinecast, spaces, rinse and knyt already do, it's installed (`/opt/homebrew/bin/xcodegen` 2.46.0), and its multiplatform support produced a working single target here. |

What your repos do (to carry over):

- `project.yml` at the root, `xcodegen generate` run by the build script before every build, and the generated `.xcodeproj` committed next to it.
- tinecast is the most modern spec: `SWIFT_VERSION: "6.0"`, `SWIFT_DEFAULT_ACTOR_ISOLATION: MainActor`, `SWIFT_APPROACHABLE_CONCURRENCY: YES`, `sources: - path: X, type: syncedFolder` (an Xcode 16+ folder reference, so adding files never touches the pbxproj), `GENERATE_INFOPLIST_FILE: YES` with `INFOPLIST_KEY_*` settings instead of an Info.plist file.
- Pure logic goes in a local package (`Packages/TineCastKit`, `Packages/SpacesCore`) that's unit-testable with `swift test` and needs no simulator.
- Signing: rinse and spaces keep `DEVELOPMENT_TEAM: ""` / `CODE_SIGN_IDENTITY: "-"` in the spec and let `build.sh` source a git-ignored `.env` (`DEVELOPMENT_TEAM=82K3YC8HVF`, `CODE_SIGN_IDENTITY=...`) that is passed as xcodebuild overrides, falling back to ad-hoc. tinecast and knyt hardcode `DEVELOPMENT_TEAM: 82K3YC8HVF` with `CODE_SIGN_STYLE: Automatic`. For an app that also targets iOS (which needs real provisioning even for a device run), the `.env` pattern is the better default because CI and the simulator stay signing-free.
- `-derivedDataPath .build` so builds don't touch `~/Library/Developer/Xcode/DerivedData`. Shipping goes through `notarize.sh` / `scripts/package.sh` (ditto, codesign `--options runtime --timestamp`, notarytool, stapler, hdiutil).

## 2. Liquid Glass and related APIs in the 27 SDK

All signatures below are copied from `SwiftUI.swiftinterface` / `SwiftUICore.swiftinterface` in `iPhoneOS27.0.sdk` and checked against `MacOSX27.0.sdk`.

### 2.1 Core glass (all iOS 26.0 / macOS 26.0, unchanged in 27)

```swift
func glassEffect(_ glass: Glass = .regular, in shape: some Shape = DefaultGlassEffectShape()) -> some View
struct Glass { static var regular, clear, identity; func tint(_ color: Color?) -> Glass; func interactive(_ isEnabled: Bool = true) -> Glass }
struct GlassEffectContainer<Content: View> { init(spacing: CGFloat? = nil, @ViewBuilder content: () -> Content) }
func glassEffectID(_ id: (some Hashable & Sendable)?, in namespace: Namespace.ID) -> some View
func glassEffectUnion(id: (some Hashable & Sendable)?, namespace: Namespace.ID) -> some View
func glassEffectTransition(_ transition: GlassEffectTransition) -> some View   // .matchedGeometry, .materialize, .identity
.buttonStyle(.glass) / .buttonStyle(.glass(_ glass: Glass)) / .buttonStyle(.glassProminent)
```

Rules that hold across your repos and Apple's guidance:

- Glass belongs on the **navigation/control layer floating over content** (toolbars, the composer, the jump button), never on content itself (message bubbles stay solid fills).
- Wrap sibling glass shapes in **one `GlassEffectContainer`** so they sample together, blend when close, and can morph. roost and tinecast both do this; tine's comment on why holds too: glass draws its own edge, so don't add a border.
- `.interactive()` gives the press/shimmer response; use it on tappable custom glass (the text field capsule), not on static panels. Buttons with `.glass` styles are already interactive.
- `glassEffectID` + `@Namespace` + `withAnimation` morphs one glass shape into another (mic ↔ send in the composer below).
- `.tint(_:)` is for conveying meaning (a primary action), not decoration. `.glassProminent` already tints with the accent colour.
- Pair button glass with `.buttonBorderShape(.circle | .capsule)` and `.controlSize(.large)` for icon-only round buttons.

### 2.2 System chrome you get for free, and its modifiers (26.0)

- **Toolbars** are glass automatically. Group items with `ToolbarSpacer(.fixed)` / `ToolbarSpacer(.flexible)` (iOS 26, macOS 26). Take an item out of the shared glass capsule with `.sharedBackgroundVisibility(.hidden)` on the `ToolbarItem`.
- **Scroll edge effect** (the blur/fade under bars): `scrollEdgeEffectStyle(_ style: ScrollEdgeEffectStyle?, for edges: Edge.Set)` with `.automatic | .soft | .hard`; `scrollEdgeEffectHidden(_ hidden: Bool = true, for edges: Edge.Set = .all)`. macOS typically wants `.hard` under a toolbar, iOS `.soft`.
- **`safeAreaBar(edge: VerticalEdge, alignment: HorizontalAlignment = .center, spacing: CGFloat? = nil, content:)`** (also a `HorizontalEdge` overload). Like `safeAreaInset`, but the scroll view's edge effect extends under the bar. This is the right host for a chat composer (tinecast's ResultsList uses it the same way).
- **`backgroundExtensionEffect()`** / `backgroundExtensionEffect(isEnabled:)`: mirrors and blurs edge content under a sidebar or inspector. For hero imagery in a detail column, not for a chat list.
- **Tabs** (if ever used): `tabBarMinimizeBehavior(.onScrollDown | .onScrollUp | .never)` (iOS only), `tabViewBottomAccessory { }` (iOS 26, `isEnabled:` overload is iOS 26.1, unavailable on macOS), `Tab(role: .search)`, `tabViewSearchActivation(_:)`, `.tabViewStyle(.sidebarAdaptable)`.
- **Sidebar**: `NavigationSplitView` gets the floating glass sidebar automatically on both platforms. Nothing to opt into.
- **Concentric shapes**: `ConcentricRectangle(...)`, `.rect(corners: .concentric)`, `containerShape(_:)` make inner shapes follow the outer glass radius. Use them for nested glass so the corners line up.
- `buttonSizing(.flexible | .fitted | .automatic)`, `controlSize(_ range:)` (26).

### 2.3 What's actually new in the 27 SDK

**No new Liquid Glass symbols.** Every `Glass*`, `glassEffect*`, `.glass`/`.glassProminent`, `scrollEdgeEffect*`, `safeAreaBar`, `backgroundExtensionEffect` declaration is still `@available(iOS 26.0, macOS 26.0, ...)`, so don't go looking for 27 glass APIs. The 27 SDK also introduces a new availability spelling, `@available(anyAppleOS 27.0, *)`. Additions relevant to this app (available on both platforms unless noted):

| API | Use here |
|---|---|
| `toolbarMinimizationBehavior(_: ToolbarMinimizationBehavior, for: ToolbarPlacement...)` (`.automatic`, `.onScrollDown`), plus `toolbarMinimizationSafeAreaAdjustment` and `toolbarMinimizationRestoration(.atScrollEdge)` | Shrink the nav bar while reading a long reply. |
| `ToolbarOverflowMenu { }`, `.toolbarOverflowMenu { }`, `ToolbarItem(...).visibilityPriority(.high/.low)` | Control which toolbar items collapse into overflow on a narrow iPhone or window. |
| `ToolbarItemPlacement.topBarPinnedTrailing` (iOS 27) | A trailing item that never collapses. |
| `textInputBorderShape(_: TextInputBorderShape)` (`.automatic`, `.capsule`, `.roundedRectangle`); `TextFieldStyle.bordered` | System-shaped text field borders; check this before hand-rolling the composer capsule. |
| `swipeActions(edge:allowsFullSwipe:content:onPresentationChanged:)` and `swipeActionsContainer()` (iOS/macOS 27) | Swipe actions on rows **outside `List`** (put `.swipeActionsContainer()` on the ScrollView). Good for per-message actions; it doesn't do the iMessage timestamp reveal. |
| `DragGesture(minimumDistance:coordinateSpace:inputKinds:)`, `GestureInputKinds` (`.directTouch`, `.indirectTouch`, `.pencil`, `.pointer`) | Restrict the timestamp drag to touch so a Mac mouse drag doesn't trigger it. |

## 3. Architecture idioms

### 3.1 Concurrency settings

With Swift 6.4, `SWIFT_VERSION 6` (strict checking) + `SWIFT_DEFAULT_ACTOR_ISOLATION: MainActor` + `SWIFT_APPROACHABLE_CONCURRENCY: YES` (copied from tinecast) is the modern UI-app setup. Everything is `@MainActor` unless you say otherwise, and `nonisolated` async functions run on the caller's actor unless marked `@concurrent`. The 27 SDK itself is written this way (`@concurrent func read(...)`, `sending` parameters all over the new Document APIs).

Practical consequences, all verified in the probe:

- Mark **plain data types and pure functions `nonisolated`** (`nonisolated struct Message: Codable, Sendable`, `nonisolated func serverSentEvents(...)`). Otherwise their `Codable` conformances are inferred main-actor-isolated and decoding them in background work fails to compile.
- Network, parsing and markdown parsing are `nonisolated`; models and views stay on the main actor. Use `@concurrent` for genuinely CPU-heavy work you want off the main actor.
- `Task { }` started from a main-actor model inherits the main actor, so mutating `@Observable` state inside a `for try await` loop needs no hops.

### 3.2 State

- `@Observable final class` for models; own them with `@State` at the App level and inject with `.environment(store)`; read with `@Environment(ChatStore.self)`. Use `@Bindable` only when you need `$store.x` bindings. No `ObservableObject`/`@Published`/`@StateObject`.
- Split by lifecycle, not by screen: one `ChatStore` (conversations, messages, streaming), one `Session`/`AuthModel` (token, user). Views stay small; per-view transient state (`draft`, scroll position) is `@State` in the view.
- No view models per view. That's the current Apple idiom, and your "functions over classes" rule agrees.

### 3.3 Navigation: one `NavigationSplitView` for both platforms

`NavigationSplitView { sidebar } detail: { chat }` collapses to a `NavigationStack` push on iPhone automatically, and is a two-column window with a glass sidebar on Mac and iPad. Add `.inspector(isPresented:content:)` (iOS 17 / macOS 14) on the detail view: it's a trailing column on Mac/iPad and a sheet on iPhone, with `.inspectorColumnWidth(min:ideal:max:)` set **inside** the inspector content. Sidebar width via `.navigationSplitViewColumnWidth(min:ideal:max:)`. Use `List(selection: $selection)` with `NavigationLink(value:)` so selection drives the detail on every size class.

The iOS favourites row is an `#if os(iOS)` horizontal `ScrollView` as the first row of the sidebar `List` (clear background, zero insets). On Mac, favourites are better as a `Section("Favourites")` in the sidebar. See `RootView` below.

### 3.4 Streaming (SSE)

`URLSession.bytes(for:)` → `bytes.lines` → keep `data:` lines → `AsyncThrowingStream`. Cancellation propagates through `onTermination` → `task.cancel()`, so cancelling the consuming task (Stop button, leaving the chat) tears down the HTTP stream. For multi-line `data:` events or `event:` names, accumulate until a blank line; the probe's version is enough for one JSON payload per event. Decode each payload with `JSONDecoder` in the nonisolated function, not on the main actor.

Coalesce UI updates if the server sends many tiny deltas. Appending per token is fine for normal rates; if profiling shows layout churn, buffer for about 50 ms before appending.

### 3.5 Persistence: simple cache over SwiftData

If the server is the source of truth for conversations, **don't use SwiftData**. Cache `[Conversation]` and recent `[Message]` per conversation as `Codable` JSON in `URL.applicationSupportDirectory` (write with `.atomic`), load on launch, replace on fetch. It's simpler, `Sendable`, and avoids `@Model` main-actor and migration overhead. Reach for SwiftData only if you need local queries/search across a large history, or offline edits that sync later. (CloudKit sharing is the knyt lesson: SwiftData has no `CKShare`.)

### 3.6 Keychain for tokens

`SecItemCopyMatching` / `SecItemUpdate` → on `errSecItemNotFound`, `SecItemAdd`, with `kSecClassGenericPassword`, service plus account, `kSecUseDataProtectionKeychain: true` (the iOS-style keychain on macOS too, so the code is identical on both platforms) and `kSecAttrAccessibleAfterFirstUnlock`. Free functions, no wrapper class (see `Keychain.swift` below).

Gotcha: on macOS the data-protection keychain needs a **team-signed** app (an application-identifier/keychain access group). Expect ad-hoc `CODE_SIGN_IDENTITY=-` builds to fail with `errSecMissingEntitlement` (-34018) (not verified in this session). This is the same class of problem as rinse's App Group needing the team prefix, and it's why `.env` with `DEVELOPMENT_TEAM=82K3YC8HVF` matters for real runs.

## 4. Chat UI specifics

### 4.1 Bottom-anchored scroll

- `ScrollView { LazyVStack { ForEach } .scrollTargetLayout() }` + **`.defaultScrollAnchor(.bottom)`**. With no role, it applies to initial offset, size changes and alignment: it opens at the newest message, short conversations sit at the bottom, and a streaming reply growing at the bottom keeps the view pinned while the user is at the bottom. Use `.defaultScrollAnchor(.bottom, for: .sizeChanges)` to apply it to one role only.
- `@State var position = ScrollPosition(idType: Message.ID.self)` + `.scrollPosition($position)`; jump with `position.scrollTo(edge: .bottom)` or `scrollTo(id:anchor:)`.
- "Am I at the bottom" comes from `onScrollGeometryChange(for: Bool.self) { $0.visibleRect.maxY >= $0.contentSize.height - 40 } action: { isAtBottom = $1 }`. Drive the jump button's visibility from that.
- Don't use a flipped/inverted ScrollView (`rotationEffect(.degrees(180))`). That was the pre-iOS-17 hack and it breaks context menus, accessibility order and text selection.
- `.scrollDismissesKeyboard(.interactively)` on iOS.

### 4.2 Jump-to-bottom glass button

An `overlay(alignment: .bottomTrailing)` button with `.buttonStyle(.glass)`, `.buttonBorderShape(.circle)`, `.labelStyle(.iconOnly)` and a scale-plus-opacity transition. Because the composer is a `safeAreaBar`, the overlay sits above it automatically. Optionally show an unread count badge when new content arrives while scrolled up.

### 4.3 iMessage swipe-left timestamps

The mechanics: one horizontal drag on the **whole list** offsets **every** row by the same amount, and each row carries its timestamp parked just off its trailing edge. Rows are clipped by the ScrollView, so the timestamps slide in from the right as the rows move left. Release springs back because the offset lives in a `@GestureState`.

- Attach it as `.simultaneousGesture(DragGesture(minimumDistance: 16).updating(...))` on the ScrollView, only acting when `|dx| > |dy|`, so vertical scrolling still wins.
- Clamp to `-timestampWidth...0`. Animate with `.interactiveSpring`.
- In real iMessage, outgoing (trailing) bubbles move and incoming ones stay put while every timestamp appears on the right. To match exactly, apply the offset only to `role == .user` rows and give incoming rows a `.trailing` overlay positioned at the screen edge. The probe offsets everything, which is the simpler and also accepted variant.
- If `simultaneousGesture` ever fights the scroll view on device (it has on some iOS versions), the robust iOS fallback is a `UIGestureRecognizerRepresentable` wrapping a `UIPanGestureRecognizer` whose `gestureRecognizerShouldBegin` only accepts horizontal velocity.
- On macOS there's no touch swipe: use `DragGesture(... inputKinds: .directTouch)` (27) to keep mouse drags from triggering it, and show the time via `.help(...)` on hover or a hover-revealed label instead.
- Use `Text(date, format: .dateTime.hour().minute())`, and day separators between groups.

### 4.4 Bubble shape

`UnevenRoundedRectangle(cornerRadii: RectangleCornerRadii(topLeading:bottomLeading:bottomTrailing:topTrailing:), style: .continuous)` with radius 20 everywhere except 4 on the "tail" corner (bottom-trailing for mine, bottom-leading for theirs). The radii are multiples of 4, per your UI rule. Make the tail corner small only on the **last bubble of a consecutive group** for the authentic look. Fill with `.tint` / `.fill.secondary`, never glass. Cap the width (`frame(maxWidth: 560)`) so replies stay readable on a wide Mac window.

### 4.5 Markdown in assistant replies

- `Text(AttributedString(markdown:))` renders **inline** markdown only (bold, italic, code spans, links, strikethrough). With the default `.full` syntax, block structure (lists, headings, code blocks, quotes, tables) is parsed into the `presentationIntent` attribute, but `Text` ignores it, so lists and code blocks collapse into one paragraph. Nothing in the 27 SDK changes that (no markdown view in SwiftUI; `MarkdownParsingOptions` is unchanged).
- **Native approach (recommended to start):** parse once with `interpretedSyntax: .full, failurePolicy: .returnPartiallyParsedIfPossible`, iterate `parsed.runs[\.presentationIntent]` (adjacent runs of the same block coalesce into one range), map each block's `PresentationIntent.components` to a small `Kind` enum, and render each block with `Text` (which keeps the inline styling). See `MarkdownText.swift` below: paragraphs, headings, nested ordered/unordered lists, code blocks in a horizontal ScrollView, quotes and rules, in about 80 lines with no dependency. Since parsing is `nonisolated`, a long reply can be parsed off-main and cached per message id once streaming finishes. During streaming, re-parsing the growing string each update is acceptable at chat sizes, and `returnPartiallyParsedIfPossible` tolerates an unclosed code fence.
- **Package, if you need tables or syntax highlighting:** gonzalezreal's **Textual** (github.com/gonzalezreal/textual), which its README calls the "spiritual successor to MarkdownUI" (swift-markdown-ui is effectively superseded). It supports code blocks with syntax-highlight themes, lists and tables. It's young (no tagged releases visible on the repo page as of today), so pin a revision. Don't add it until the native renderer actually falls short.
- Enable `.textSelection(.enabled)`. It works on both platforms and gives copy support for free.

### 4.6 Glass composer with mic and send

- Host it in `.safeAreaBar(edge: .bottom)` plus `.scrollEdgeEffectStyle(.soft, for: .bottom)` so messages blur under it.
- One `GlassEffectContainer(spacing: 8)`: a `TextField(axis: .vertical)` with `.lineLimit(1...6)`, `.textFieldStyle(.plain)`, padded and wrapped in `.glassEffect(.regular.interactive(), in: .rect(cornerRadius: 22))`, next to a round button that's **mic (`.glass`) when empty and send (`.glassProminent`) when there's text**. Both share `glassEffectID("action", in: namespace)` so the swap morphs, animated with `.animation(.smooth, value: canSend)`.
- Return to send: `.onSubmit`. On Mac add `.keyboardShortcut(.return, modifiers: .command)` to the send button. Return-versus-newline behaviour of a vertical-axis TextField differs between the platforms and keyboards, so test it on both. If it needs pinning down, add an `.onKeyPress(.return)` handler that sends unless Shift is held.
- Dictation: `SpeechAnalyzer` + `SpeechTranscriber` (Speech framework, iOS/macOS 26) with `AVAudioEngine`. It needs `NSMicrophoneUsageDescription` / `NSSpeechRecognitionUsageDescription` and, on macOS, `ENABLE_RESOURCE_ACCESS_AUDIO_INPUT`. Not compiled in the probe.
- While streaming, swap send for a stop button that cancels `store.streamingTask`.

### Models.swift

```swift
import Foundation
import Observation

nonisolated enum Role: String, Codable, Sendable {
    case user
    case assistant
}

nonisolated struct Message: Identifiable, Codable, Sendable, Equatable {
    let id: UUID
    let role: Role
    var text: String
    let sentAt: Date
}

nonisolated struct Conversation: Identifiable, Codable, Sendable, Hashable {
    let id: UUID
    var title: String
    var isFavourite: Bool
}

@Observable
final class ChatStore {
    var conversations: [Conversation] = []
    var messages: [Conversation.ID: [Message]] = [:]
    var streamingTask: Task<Void, Never>?

    func send(_ text: String, in conversationID: Conversation.ID, endpoint: URL) {
        let reply = Message(id: UUID(), role: .assistant, text: "", sentAt: .now)
        messages[conversationID, default: []] += [Message(id: UUID(), role: .user, text: text, sentAt: .now), reply]
        streamingTask = Task {
            do {
                for try await delta in serverSentEvents(for: URLRequest(url: endpoint)) {
                    append(delta, to: reply.id, in: conversationID)
                }
            } catch {
                append("\n\n_\(error.localizedDescription)_", to: reply.id, in: conversationID)
            }
        }
    }

    private func append(_ delta: String, to messageID: Message.ID, in conversationID: Conversation.ID) {
        guard let index = messages[conversationID]?.firstIndex(where: { $0.id == messageID }) else { return }
        messages[conversationID]?[index].text += delta
    }
}
```

```swift
import SwiftUI

nonisolated struct MarkdownBlock: Identifiable {
    let id: Int
    let kind: Kind
    let content: AttributedString

    enum Kind: Equatable {
        case paragraph
        case heading(level: Int)
        case listItem(marker: String, depth: Int)
        case code(language: String?)
        case quote
        case rule
    }
}

nonisolated func markdownBlocks(from source: String) -> [MarkdownBlock] {
    let options = AttributedString.MarkdownParsingOptions(interpretedSyntax: .full, failurePolicy: .returnPartiallyParsedIfPossible)
    guard let parsed = try? AttributedString(markdown: source, options: options) else {
        return [MarkdownBlock(id: 0, kind: .paragraph, content: AttributedString(source))]
    }
    return parsed.runs[\.presentationIntent].enumerated().map { offset, run in
        let (intent, range) = run
        let components = intent?.components ?? []
        let listDepth = components.filter { $0.kind == .orderedList || $0.kind == .unorderedList }.count
        let isOrdered = components.first { $0.kind == .orderedList || $0.kind == .unorderedList }?.kind == .orderedList
        let kind: MarkdownBlock.Kind = components.lazy.compactMap { component -> MarkdownBlock.Kind? in
            switch component.kind {
            case .header(let level): .heading(level: level)
            case .codeBlock(let language): .code(language: language)
            case .listItem(let ordinal): .listItem(marker: isOrdered ? "\(ordinal)." : "•", depth: listDepth)
            case .blockQuote: .quote
            case .thematicBreak: .rule
            default: nil
            }
        }.first ?? .paragraph
        return MarkdownBlock(id: offset, kind: kind, content: AttributedString(parsed[range]))
    }
}

struct MarkdownText: View {
    let source: String

    var body: some View {
        VStack(alignment: .leading, spacing: 8) {
            ForEach(markdownBlocks(from: source)) { block in
                switch block.kind {
                case .paragraph:
                    Text(block.content)
                case .heading(let level):
                    Text(block.content).font(level == 1 ? .title3.bold() : .headline)
                case .listItem(let marker, let depth):
                    HStack(alignment: .firstTextBaseline, spacing: 6) {
                        Text(marker).monospacedDigit()
                        Text(block.content)
                    }
                    .padding(.leading, CGFloat(depth - 1) * 16)
                case .code:
                    ScrollView(.horizontal) {
                        Text(String(block.content.characters).trimmingCharacters(in: .newlines))
                            .font(.callout.monospaced())
                            .padding(8)
                    }
                    .background(.background.secondary, in: .rect(cornerRadius: 8))
                case .quote:
                    Text(block.content)
                        .foregroundStyle(.secondary)
                        .padding(.leading, 8)
                        .overlay(alignment: .leading) { Capsule().fill(.tertiary).frame(width: 3) }
                case .rule:
                    Divider()
                }
            }
        }
        .textSelection(.enabled)
    }
}
```

### ServerSentEvents.swift

```swift
import Foundation

nonisolated func serverSentEvents(for request: URLRequest, session: URLSession = .shared) -> AsyncThrowingStream<String, Error> {
    AsyncThrowingStream { continuation in
        let task = Task {
            do {
                var streamRequest = request
                streamRequest.setValue("text/event-stream", forHTTPHeaderField: "Accept")
                let (bytes, response) = try await session.bytes(for: streamRequest)
                guard let http = response as? HTTPURLResponse, (200..<300).contains(http.statusCode) else {
                    throw URLError(.badServerResponse)
                }
                for try await line in bytes.lines {
                    guard line.hasPrefix("data:") else { continue }
                    let payload = line.dropFirst(5).trimmingCharacters(in: .whitespaces)
                    if payload == "[DONE]" { break }
                    continuation.yield(payload)
                }
                continuation.finish()
            } catch {
                continuation.finish(throwing: error)
            }
        }
        continuation.onTermination = { _ in task.cancel() }
    }
}
```

### Keychain.swift

```swift
import Foundation
import Security

nonisolated let keychainService = "dev.gustaf.Probe"

nonisolated func readToken(account: String) -> String? {
    let query: [CFString: Any] = [
        kSecClass: kSecClassGenericPassword,
        kSecAttrService: keychainService,
        kSecAttrAccount: account,
        kSecUseDataProtectionKeychain: true,
        kSecReturnData: true,
        kSecMatchLimit: kSecMatchLimitOne,
    ]
    var result: CFTypeRef?
    guard SecItemCopyMatching(query as CFDictionary, &result) == errSecSuccess, let data = result as? Data else { return nil }
    return String(decoding: data, as: UTF8.self)
}

nonisolated func saveToken(_ token: String, account: String) throws {
    let query: [CFString: Any] = [
        kSecClass: kSecClassGenericPassword,
        kSecAttrService: keychainService,
        kSecAttrAccount: account,
        kSecUseDataProtectionKeychain: true,
    ]
    let attributes: [CFString: Any] = [
        kSecValueData: Data(token.utf8),
        kSecAttrAccessible: kSecAttrAccessibleAfterFirstUnlock,
    ]
    let status = SecItemUpdate(query as CFDictionary, attributes as CFDictionary)
    if status == errSecItemNotFound {
        let addStatus = SecItemAdd(query.merging(attributes) { $1 } as CFDictionary, nil)
        guard addStatus == errSecSuccess else { throw NSError(domain: NSOSStatusErrorDomain, code: Int(addStatus)) }
        return
    }
    guard status == errSecSuccess else { throw NSError(domain: NSOSStatusErrorDomain, code: Int(status)) }
}
```
